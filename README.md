# EMCL Desktop

Простое настольное приложение Avalonia UI для просмотра объектов счётчика DLMS/COSEM.

## Запуск

Нужен .NET SDK 10. Репозитории `EMCLDesktop` и `EMCL` должны лежать рядом:

```text
Repositories/
  EMCLDesktop/
  EMCL/
```

```sh
dotnet restore EMCLDesktop.Desktop/EMCLDesktop.Desktop.csproj
dotnet run --project EMCLDesktop.Desktop/EMCLDesktop.Desktop.csproj
```

Проект `EMCLDesktop.Desktop` использует Avalonia Desktop и предназначен для Windows, Linux и macOS. Для конкретной платформы собирайте и запускайте его с установленным .NET 10. Остальные проекты шаблона (Android, iOS, Browser) в этом сценарии не используются.

## Работа с прибором

Над каталогом во вкладке «Объекты» находятся кнопки «Параметры подключения», «Загрузить» и «Сохранить». Параметры подключения и обмена открываются в отдельном модальном окне. Изменения используются при следующем подключении; окно закрывается кнопкой «Готово» или Escape. Кнопка «Сохранить» записывает параметры и снимок каталога объектов: OBIS, классы, атрибуты, методы, права доступа и уже считанные текстовые значения. Пароль тоже записывается в JSON, поэтому храните файл соответственно. «Загрузить» открывает сохранённый снимок без подключения к прибору; также поддерживаются файлы с прежним идентификатором `EMCLDirector` и оба формата `EMCL.Examples`. После успешного подключения выбранная рабочая вкладка остаётся открытой.

В параметрах подключения выберите `TCP` или `Serial`. Для TCP отображаются IP/имя хоста и TCP-порт; для Serial — выпадающий список доступных портов (`COM3`, `/dev/ttyUSB0`, `/dev/cu.usbserial…`) с кнопкой «Обновить», BaudRate, DataBits, Parity, StopBits, Handshake, DTR и RTS. При аппаратном Handshake линия RTS управляется автоматически. Настройки каждого транспорта сохраняются в полях при переключении; в JSON записываются параметры выбранного транспорта. Старые TCP-конфигурации загружаются без изменений. Для обоих транспортов доступны Wrapper или HDLC, адреса клиента и сервера и версия Association LN. Serial использует прямой бинарный обмен с заданной скоростью без начального обмена IEC 62056-21 и переключения скорости. Для HDLC можно указать физический адрес сервера и расширенный формат. Поддерживаются `None`, `Low` и `High` аутентификация с паролем UTF-8, hex-байтами или именем переменной окружения; `High` требует 16 байт секрета.

Все поддерживаемые флаги Conformance включены по умолчанию. Их можно переключать по отдельности; при загрузке JSON-конфига набор флажков принимает значения из него. Для чтения ассоциации необходим `Get`, а для `High`-аутентификации также `Action`.

Справа от вкладок отдельно показаны состояние соединения и кнопка с действием «Подключиться» / «Отключиться». Индикатор серо-синий без соединения, зелёный при подключении и голубой во время подключения или отключения; переходные состояния подписаны «Подключение…» и «Отключение…». Во время операций и чтения кнопка недоступна, а индикатор продолжает показывать состояние соединения. Подключение устанавливает ассоциацию без чтения `object_list`. Кнопка «Считать дерево» во вкладке «Объекты» запрашивает `object_list` через активное соединение и обновляет каталог. Сохранённый каталог остаётся на экране после подключения до отдельного чтения дерева. При отключении или неудачном повторном подключении уже загруженный каталог остаётся доступным для просмотра и сохранения. Приборы, повторяющие полностью одинаковые записи, можно обработать с помощью флажка в параметрах обмена. Во вкладке «Объекты» каталог сгруппирован по классу COSEM и версии. Поиск охватывает OBIS, имя и ID класса; флажок RegExp включает регулярные выражения. Выбор объекта показывает атрибуты и методы с их правами и типами без чтения значений. Кнопка «Считать все атрибуты» отправляет GET для атрибутов объекта; кнопка «Считать» делает это для одного атрибута. Кнопки доступны независимо от предварительной оценки прав: фактический отказ прибора отображается у атрибута. У неизвестных классов тип атрибута определяется по успешному ответу. Вызов методов пока не реализован.

Вкладка **«Инспектор пакетов»** имеет два независимых источника:

- **«Анализировать текущее подключение»** — пассивно разбирает захваченные TCP/Serial-байты последнего подключения. Кадры восстанавливаются независимо от границ транспортных чтений. После отключения результат остаётся доступным; новое подключение начинает отдельный анализ. Декодирование выполняется в фоне при открытой вкладке, а захват продолжается на всех вкладках.
- **«Анализировать текст»** — разбирает вставленный лог по кнопке «Разобрать». Поддерживаются HEX с пробелами, слитный HEX, `0xNN`, TX/RX, SEND/RECV и стрелки направления; временные метки, размеры и смещения собственного экспорта не попадают в данные. Посторонние строки пропускаются, их количество выводится в результате. После успешного разбора поле ввода сворачивается. Текст, результат и выбор пакета/поля сохраняются при переключении источников.

Слева находятся список пакетов и дерево полей HDLC / Wrapper / LLC / ACSE / DLMS / A-XDR. OBIS, атрибут или метод, значения и диагностика находятся в «Структуре пакета»; контекст запроса и значение с учётом scaler/unit также добавляются в это дерево. Метаданные из другого пакета не получают вымышленные диапазоны байтов в текущем ответе. Справа показаны HEX, диапазон выбранного поля и переходы между связанными пакетами; исходный текст всегда виден внизу без раскрытия секции. При наведении на поле выделяются его байты; при наведении на байт — соответствующее поле и его значение слева. Клик закрепляет выделение. Смещения отсчитываются от нуля. HEX показывается страницами по 256 байт; наведение на поле с другой страницы переводит к его байтам, также доступна кнопка «К байтам поля».

Инспектор поддерживает normal GET/SET/ACTION, GET next/block, HDLC-сегментацию, уведомления, AARQ/AARE и другие ACSE-конверты, вложенные массивы, структуры и compact array. Собранные APDU/значения отображаются отдельными записями с переходами к исходным кадрам/блокам. Их HEX содержит исходные пакеты последовательно; поля могут занимать несколько разорванных диапазонов, исключая транспортные заголовки и CRC. При нарушении порядка сегментов/блоков значение не объявляется успешно собранным.

OBIS ответа определяется по запросу с тем же Invoke ID в пределах соединения и пары адресов. При отсутствующем запросе, неоднозначном Invoke ID или повреждённом кадре контекст не придумывается. Число остаётся исходным, пока в предыдущем обмене не найдены scaler/unit соответствующего регистра. Защищённые APDU и неподдерживаемые EMCL варианты показываются как исходные байты с диагностикой, без мнимой расшифровки. Недостающие возможности EMCL описаны в `Documents/ChatGPT/EMCLDesktop/Tasks/EMCL-offline-packet-inspector.md` рабочего пространства. Ограничения одного разбора: 16 миллионов символов текста, 50000 записей, 1 МиБ на собранное сообщение и 4096 сегментов/блоков; разметка значений ограничена 10000 узлов и глубиной 64.

Отдельная вкладка **«Трассировка и экспорт»** показывает трассировку всего обмена с момента запуска приложения независимо от выбранного формата: сообщения диагностики и точные переданные и принятые байты TCP/Serial с направлением, временем, длиной фрагмента и смещением строки. Поле трассировки занимает всю доступную высоту, сверху расположены выбор формата и кнопки копирования и сохранения. Попытка отправки записывается до записи в транспорт; успешное завершение отмечается отдельно. Если запись завершилась ошибкой, реально отправленный префикс неизвестен. Захват начинается до установления HDLC/ассоциации; границы чтений транспорта могут не совпадать с границами пакетов. Журнал хранится в памяти без обрезания и сохраняется при переподключении до закрытия приложения. Для сохранения на диск используйте «Сохранить трассировку».

Вместо крупной шапки сверху находятся вкладки и компактная кнопка подключения. Сообщения о состоянии и ошибках работы со счётчиком показываются только во вкладке «Объекты», освобождая место в инспекторе и трассировке.

Блок текущего статуса расположен в одной сетке с каталогом и сведениями об объекте: его края совпадают с внешними краями двух колонок. Кнопка «Копировать» появляется только для сообщения об ошибке и скрывается при следующем обычном сообщении или успешном действии.

Селект формата применяется ко всей уже записанной истории, копированию и сохранению `.txt`:

- **Словесный** — описание подключения и обмена: настройки без пароля, количество байтов TCP/Serial, HDLC-кадры, параметры UA, типы APDU и диагностика AARE. HEX-дампы не выводятся.
- **Словесный + HEX** — те же описания и все исходные байты TCP/Serial без маскирования, с временем, направлением, длиной фрагмента и смещением строки.
- **Чистый HEX TX/RX** — только строки `TX: 7E …` / `RX: 7E …`: направление и исходные байты без маскирования. В этом формате нет временных меток, размеров, смещений и словесных сообщений. Длинные фрагменты разбиваются на строки по 64 байта; направление повторяется на каждой строке.

По умолчанию выбран словесный формат. Оба HEX-режима показывают весь записанный обмен, включая переданные по сети пароли и ключи. Переключение формата не влияет на захват или соединение. Неограниченный журнал расходует память пропорционально объёму обмена.

У Profile Generic есть отдельное чтение: весь буфер, первые N записей, последние N записей, интервал по номерам или диапазон дат. Для последних N приложение сначала читает `entries_in_use`, для дат — выбирает столбец времени из `capture_objects` и часовой пояс счётчика. Диапазоны отправляются счётчику через DLMS selective access; нужен согласованный флаг `SelectiveAccess` в Conformance. Приложение автоматически читает `capture_objects`, если они ещё не получены. Таблица подписывает столбцы OBIS источника и именем захватываемого атрибута и показывает по 100 строк на странице. Поддерживаются обычный массив и compact array.

Поле «Без обмена» задаёт паузу без чтения или записи байтов, после которой соединение прерывается. Каждый принятый фрагмент и отправка сбрасывают этот таймер; полный обмен может длиться дольше указанного интервала.

KeepAlive включён по умолчанию: после 20 секунд простоя приложение читает `logical_name` объекта Association LN коротким DLMS GET-запросом. Интервал настраивается в окне «Параметры подключения» от 1 до 3600 секунд. Во время чтения атрибутов и профилей дополнительные запросы не отправляются. Если KeepAlive обнаруживает потерю сессии, приложение показывает ошибку, закрывает старое соединение и позволяет подключиться снова без нажатия «Отключиться».

Биты защиты доступа Association LN v3 отображаются, но защищённые GET-запросы не выполняются: текущий клиент EMCL не выполняет шифрованный или подписанный обмен. Большие коллекции сокращаются только при отображении; пределы декодирования задаёт EMCL.
