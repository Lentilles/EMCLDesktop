# EMCL Desktop

Настольное приложение для работы со счётчиками DLMS/COSEM на базе Avalonia UI и библиотеки EMCL. Позволяет читать объекты и профили прибора, просматривать сохранённый каталог без подключения, анализировать пакеты и экспортировать трассировку обмена.

Desktop-проект предназначен для Windows, Linux и macOS. Проекты Android, iOS и Browser присутствуют в решении как часть исходного шаблона; инструкции ниже относятся к `EMCLDesktop.Desktop`.

## Возможности

- Подключение по TCP или последовательному порту с кадрированием Wrapper / HDLC.
- Association LN версий 1 и 3, аутентификация `None`, `Low` и `High`.
- Каталог объектов с поиском по OBIS, имени и ID класса, в том числе регулярными выражениями.
- Чтение отдельных атрибутов, всех атрибутов объекта и таблиц Profile Generic.
- Сохранение параметров подключения и снимка каталога в JSON, просмотр снимка без прибора.
- Инспектор пакетов текущего подключения и текстовых HEX-логов с выделением полей и соответствующих байтов.
- Трассировка TCP/Serial в словесном и HEX-форматах, копирование и сохранение в `.txt`.

## Запуск из исходников

Нужен .NET SDK 10. Репозитории `EMCLDesktop` и `EMCL` должны лежать рядом: приложение ссылается на `../EMCL/src/EMCL/EMCL.csproj`, готовый NuGet-пакет вместо этой зависимости не используется.

```text
Repositories/
  EMCLDesktop/
  EMCL/
    src/EMCL/EMCL.csproj
```

Выполните из корня `EMCLDesktop`:

```sh
dotnet restore EMCLDesktop.Desktop/EMCLDesktop.Desktop.csproj
dotnet run --project EMCLDesktop.Desktop/EMCLDesktop.Desktop.csproj
```

Собирайте именно Desktop-проект: сборка всего решения также затронет проекты мобильных платформ и браузера и может потребовать дополнительные workloads.

## Сборка релиза

Пример автономной сборки для macOS на Apple Silicon, не требующей установленного .NET на машине пользователя:

```sh
dotnet publish EMCLDesktop.Desktop/EMCLDesktop.Desktop.csproj -c Release -r osx-arm64 --self-contained true -o artifacts/osx-arm64
```

Для другой платформы замените идентификатор после `-r` и каталог после `-o`:

| Платформа | Идентификатор |
| --- | --- |
| macOS, Apple Silicon | `osx-arm64` |
| macOS, Intel | `osx-x64` |
| Windows, x64 | `win-x64` |
| Windows, ARM64 | `win-arm64` |
| Linux, x64 | `linux-x64` |
| Linux, ARM64 | `linux-arm64` |

Команда создаёт каталог публикации с исполняемым файлом и зависимостями. Распространять нужно весь каталог. Упаковка в macOS `.app` / `.dmg`, установщик, подпись и нотаризация в проекте пока не автоматизированы. Автономная сборка включает .NET, но системные графические библиотеки и драйвер последовательного адаптера при необходимости устанавливаются отдельно.

## Первое подключение

1. Откройте вкладку **«Объекты»** и нажмите **«Параметры подключения»**.
2. Выберите транспорт, кадрирование, адреса и аутентификацию для своего прибора. Закройте окно кнопкой **«Готово»** или Escape.
3. Нажмите **«Подключиться»** справа от вкладок. Это устанавливает ассоциацию без чтения `object_list`.
4. Нажмите **«Считать дерево»**, чтобы загрузить каталог объектов через активное соединение.
5. Выберите объект и нажмите **«Считать»** у нужного атрибута или **«Считать все атрибуты»**.

Выбор объекта сам по себе не читает значения. Сохранённый каталог остаётся на экране после подключения до отдельного чтения дерева, а также после отключения или неудачного повторного подключения. Рабочая вкладка после подключения не переключается. Состояние соединения отображается рядом с кнопкой подключения; сообщения и ошибки работы со счётчиком — во вкладке «Объекты». Сообщение об ошибке можно скопировать отдельной кнопкой.

## Параметры подключения

| Группа | Настройки |
| --- | --- |
| TCP | IP-адрес или имя хоста, TCP-порт |
| Serial | Список портов с обновлением, BaudRate, DataBits, Parity, StopBits, Handshake, DTR и RTS |
| Кадрирование | Wrapper или HDLC; для HDLC — физический адрес сервера и расширенный формат адреса |
| Ассоциация | Адреса клиента и сервера, версия Association LN, OBIS ассоциации, Conformance, максимальный размер PDU |
| Аутентификация | `None`, `Low`, `High`; пароль в UTF-8, HEX или имя переменной окружения |
| Обмен | Тайм-аут подключения, интервал «Без обмена», KeepAlive, обработка одинаковых записей `object_list` |

Для `High` нужен секрет длиной 16 байт. Все поддерживаемые флаги Conformance включены по умолчанию и переключаются по отдельности; при загрузке JSON они восстанавливаются из файла. Для чтения ассоциации необходим `Get`, а для `High` также `Action`.

Serial использует прямой бинарный обмен с заданной скоростью, без начального обмена IEC 62056-21 и переключения скорости. При аппаратном Handshake линия RTS управляется автоматически. Настройки TCP и Serial сохраняются в полях при переключении транспорта; в JSON записываются настройки выбранного транспорта.

Поле **«Без обмена»** задаёт допустимую паузу без чтения или записи байтов. Каждый принятый фрагмент и отправка сбрасывают таймер; полный запрос может выполняться дольше указанного интервала.

**KeepAlive** по умолчанию после 20 секунд простоя читает `logical_name` объекта Association LN коротким GET-запросом. Интервал настраивается от 1 до 3600 секунд. Во время чтения атрибутов и профилей дополнительные запросы не отправляются. При потере сессии приложение показывает ошибку, закрывает соединение и позволяет подключиться повторно.

## Объекты и Profile Generic

Каталог сгруппирован по классу COSEM и версии. Поиск учитывает OBIS, имя и ID класса; флажок **«Регулярное выражение»** включает поиск по шаблону. В сведениях об объекте показаны атрибуты, методы, типы и права доступа. Кнопки чтения доступны независимо от предварительной оценки прав: фактический отказ прибора отображается у атрибута. У неизвестных классов тип атрибута определяется по успешному ответу. Флажок обработки одинаковых записей позволяет игнорировать полностью совпадающие повторы в `object_list`.

Для Profile Generic доступны чтение всего буфера, первых или последних N записей, интервала по номерам и диапазона дат. Для последних N приложение сначала читает `entries_in_use`; для диапазона дат используются столбец времени из `capture_objects` и часовой пояс счётчика. Если `capture_objects` ещё не получены, приложение читает их автоматически.

Диапазоны передаются прибору через DLMS selective access; необходим согласованный флаг `SelectiveAccess` в Conformance. Таблица показывает по 100 строк на странице, подписывает столбцы OBIS источника и именем захватываемого атрибута. Поддерживаются обычный массив и compact array.

## Сохранение и загрузка

Кнопка **«Сохранить»** записывает в JSON параметры подключения и снимок каталога: OBIS, классы, атрибуты, методы, права доступа и уже считанные текстовые значения. **«Загрузить»** открывает снимок без подключения к прибору. Поддерживаются прежний идентификатор формата `EMCLDirector`, оба формата `EMCL.Examples` и старые TCP-конфигурации.

При выборе UTF-8 или HEX пароль записывается в JSON без шифрования. Режим `Environment` сохраняет имя переменной окружения вместо значения секрета.

## Инспектор пакетов

Вкладка **«Инспектор пакетов»** поддерживает два независимых источника:

- **«Анализировать текущее подключение»** — пассивный разбор захваченных TCP/Serial-байтов последнего подключения. Кадры восстанавливаются независимо от границ транспортных чтений. После отключения результат остаётся доступным; новое подключение начинает отдельный анализ. Декодирование выполняется в фоне при открытой вкладке, захват продолжается на всех вкладках.
- **«Анализировать текст»** — разбор вставленного лога по кнопке **«Разобрать»**. Поддерживаются HEX с пробелами, слитный HEX, `0xNN`, TX/RX, SEND/RECV и стрелки направления. Временные метки, размеры и смещения собственного экспорта не попадают в данные. Посторонние строки пропускаются, их количество выводится в результате. После успешного разбора поле ввода сворачивается.

Текст, результаты и выбор пакета/поля сохраняются при переключении источников. Слева показаны пакеты и дерево полей HDLC / Wrapper / LLC / ACSE / DLMS / A-XDR, справа — HEX и переходы между связанными пакетами. Исходный текст пакета доступен внизу.

Наведение на поле выделяет его байты, наведение на байт — соответствующее поле и значение. Клик закрепляет выделение. Смещения отсчитываются от нуля; HEX отображается страницами по 256 байт. Наведение на поле с другой страницы переводит к его байтам, также доступна кнопка **«К байтам поля»**. Контекст запроса, OBIS, атрибут или метод, значения, scaler/unit и диагностика находятся в дереве структуры. Метаданные из другого пакета не получают диапазоны байтов в текущем ответе.

Инспектор разбирает normal GET/SET/ACTION, GET next/block, HDLC-сегментацию, уведомления, AARQ/AARE и другие ACSE-конверты, вложенные массивы, структуры и compact array. Собранные APDU и значения показаны отдельными записями с переходами к исходным кадрам и блокам. Их HEX содержит исходные пакеты последовательно, а поля могут занимать несколько разорванных диапазонов, исключая транспортные заголовки и CRC. При нарушении порядка сегментов или блоков значение не считается успешно собранным.

OBIS ответа определяется по запросу с тем же Invoke ID в пределах соединения и пары адресов. При отсутствующем запросе, неоднозначном Invoke ID или повреждённом кадре контекст не подставляется. Число остаётся исходным, пока в предыдущем обмене не найдены scaler/unit соответствующего регистра. Защищённые APDU и неподдерживаемые варианты показываются исходными байтами с диагностикой.

Ограничения одного разбора: `16 × 1024 × 1024` символов текста, 50 000 записей, 1 МиБ на собранное сообщение и 4096 сегментов/блоков. Разметка значений ограничена 10 000 узлов и глубиной 64.

## Трассировка и экспорт

Вкладка **«Трассировка и экспорт»** показывает историю обмена с момента запуска приложения. Захват начинается до установления HDLC/ассоциации, продолжается независимо от выбранной вкладки и формата отображения, сохраняется при переподключении. Для экспорта доступны копирование и **«Сохранить трассировку»** в `.txt`.

Формат применяется ко всей уже записанной истории, копированию и сохранению:

| Формат | Содержимое |
| --- | --- |
| Словесный (по умолчанию) | Настройки подключения без пароля, объём обмена, HDLC-кадры, параметры UA, типы APDU и диагностика AARE; без HEX-дампов |
| Словесный + HEX | Те же описания и исходные байты TCP/Serial с временем, направлением, длиной фрагмента и смещением строки |
| Чистый HEX TX/RX | Только строки `TX: 7E …` / `RX: 7E …`, без времени, размеров, смещений и словесных сообщений; длинные фрагменты разбиваются по 64 байта |

Попытка отправки записывается до записи в транспорт, успешное завершение отмечается отдельно. При ошибке записи реально отправленный префикс неизвестен. Границы чтений транспорта могут не совпадать с границами пакетов.

Оба HEX-режима показывают исходный обмен без маскирования, включая переданные пароли и ключи. Журнал хранится в памяти без обрезания до закрытия приложения, поэтому потребление памяти растёт с объёмом обмена.

## Ограничения

- Запись атрибутов и вызов методов в интерфейсе пока не реализованы. Разбор SET/ACTION в инспекторе не означает возможность их отправки из приложения.
- Биты защиты доступа Association LN v3 отображаются, но защищённые GET-запросы не выполняются: текущий клиент EMCL не выполняет шифрованный или подписанный обмен.
- Большие коллекции сокращаются при отображении; пределы декодирования задаёт EMCL.
- Инспектор не расшифровывает защищённые APDU, а показывает исходные байты и диагностику.

## Проверки

В репозитории есть консольный набор проверок трассировки, транспортного тайм-аута, конфигураций, моделей представления, профилей и инспектора пакетов:

```sh
dotnet run --project Tests/TraceChecks/TraceChecks.csproj
```

Проверки используют тестовые данные и подставные транспорты, реальный счётчик не требуется.
